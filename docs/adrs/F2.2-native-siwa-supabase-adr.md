# F2.2 — Native Sign in with Apple → Supabase (no Services ID in V1 mobile path)

---

## 1. Decision

For Nomade V1 **iOS**, Sign in with Apple uses **Apple Authentication Services (native)** and Supabase Auth **`signInWithIdToken`** against **`nomade-dev`** (and later a separate prod config).

| Topic | Locked for F2.2 / V1 iOS |
|---|---|
| Client flow | Native SIWA → Apple identity token → Supabase session |
| Apple Developer | App ID + **Sign in with Apple** capability for bundle `com.izaya.Nomade` |
| Supabase Apple provider | Enabled; **Client IDs** = iOS App ID / bundle ID(s) |
| Services ID | **Not required** for native-only; **do not create** in F2.2 |
| Sign in with Apple Key (`.p8`) + client-secret JWT | **Not required** for native-only; **do not create** in F2.2 |
| OAuth redirect / callback URL | Unused by native path; register only when web/Android OAuth is deliberately added |
| Env boundary | Configure **`nomade-dev` only** in F2.2; prod is a separate human gate with separate credentials |

Changing to web OAuth / Services ID requires a revised ADR (and 6-month Apple secret rotation ops).

---

## 2. Context

F2.1 locked “Sign in with Apple via Supabase Auth” and left Bundle ID / Services ID / callbacks to the F2.2 runbook. Supabase documents two families:

1. **Native** (iOS/macOS): App ID in Client IDs; no OAuth secret.  
2. **OAuth / web / Android**: Services ID, signing key, generated secret JWT (rotate ≤ 6 months).

Nomade’s primary client is native iOS. Adding Services ID/Key now would create secrets Cap/Theo must never handle and ops debt before any web SIWA exists.

---

## 3. Consequences

**Positive**

- Smaller secret surface (no `.p8` in F2.2).  
- Matches Supabase Swift guidance.  
- Aligns with F2.1 happy path diagram (identity token → Supabase).

**Negative / follow-ups**

- Web SIWA later needs a new task + this ADR revision.  
- Hide-my-email relay domain registration may still be needed for polish; track when first E2E test hits relay mail.

**Explicit non-goals**

- Prod Apple/Supabase Auth config.  
- Bootstrap schema (F2.3).  
- iOS UI (F2.4).

## 5. Amendment (F2.6r — 2026-09-30)

Native login is **unchanged**: still no Services ID, still Supabase `signInWithIdToken`. The F2.2 row “do not create a `.p8`” applied to **login**.

F2.6r **does** require a Sign in with Apple **Key** (`.p8`) on the **server only**, to mint a short-lived ES256 `client_secret` and call Apple `/auth/revoke` during soft-delete (`POST /api/account/delete`). `client_id` and JWT `sub` are the App ID **`com.izaya.Nomade`**, not a Services ID. The Key is not bundled in iOS and is not used for login. Production Key / `nomade-prod` stay a separate human gate.

See [`../runbooks/F2.6r-apple-token-revoke-runbook.md`](../runbooks/F2.6r-apple-token-revoke-runbook.md).
