## Part A — Apple Developer (Isaias)

Official reference: [Supabase — Sign in with Apple (Swift / native)](https://supabase.com/docs/guides/auth/social-login/auth-apple) → section **Using native sign in with Apple in Swift** / **Configuration**.

### A1. Confirm Team ID

1. Open [Apple Developer](https://developer.apple.com/account) → Membership details.
2. Confirm **Team ID** matches Xcode (`LXT8T4YQR6`) or record the live Team ID in Keeper if different.
3. **Do not** paste Team ID into git if policy prefers Keeper-only — Cap already has the Xcode value as a non-secret expected default; reply checklist may confirm “matches Xcode: yes/no”.

### A2. App ID with Sign in with Apple

1. Identifiers → **App IDs** → find or create App ID for bundle **`com.izaya.Nomade`**.
2. Capabilities: enable **Sign in with Apple**.
3. Server-to-Server Notification Endpoint: **leave blank** (Supabase Auth does not support it yet).
4. Save.

### A3. Explicitly skip (native-only)

Do **not** create in F2.2 unless Cap revises this runbook:

- Services ID (web OAuth)
- Keys → Sign in with Apple (`.p8`)
- Website URLs / return URLs for Services ID
- Email Sources for Apple relay (can wait until hide-my-email is tested end-to-end)

Skipping these avoids `.p8` secret surface and 6-month OAuth secret rotation until web SIWA is needed.

### A4. Xcode entitlement checklist (record now; wire in F2.4)

For Cap/Theo docs and Isaias later:

- [ ] Target `Nomade` → Signing & Capabilities → **Sign in with Apple** capability present (or add in F2.4).
- [ ] `PRODUCT_BUNDLE_IDENTIFIER` remains `com.izaya.Nomade` (Debug + Release).
- [ ] No `.p8` or Auth Key files in the iOS repo / app bundle.

F2.2 does **not** require shipping the entitlement PR; documenting the checklist is enough.
