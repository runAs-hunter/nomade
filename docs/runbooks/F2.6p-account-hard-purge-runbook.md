## Goal

Within **≤ 30 days** of a verified soft-delete request (F0.2 Class B), hard-purge `pending_deletion` rows so Class B personal data is deleted or irreversibly de-identified, Supabase Auth `admin.deleteUser` is called (so a later Sign in with Apple mints a **new** UUID), `deletion_status → deleted`, legal holds are honoured if a flag exists (stub if none), and stripped Class E/G rows are retained per F0.2 when those domains exist.

**Complete when:**

1. Daily cron (Vercel Cron → protected Next.js route) scans `internal.users` where `deletion_status = 'pending_deletion'` and `deleted_at <= now() - 24 hours`, and purges each eligible row.  
2. Per eligible user, in order: optional legal-hold skip → scrub Class B PII on `internal.users` + **DELETE** that user’s `auth_identities` rows → wipe stubs for journey/chat/billing (no-ops today) → `auth.admin.deleteUser(userId)` via service_role → set `deletion_status = 'deleted'` (keep row; leave `deleted_at`).  
3. Idempotent: already `deleted` → skip success; Auth user already gone → treat Auth step as success.  
4. Route is **cron-only**: `GET|POST /api/cron/purge-accounts` gated by `Authorization: Bearer ${CRON_SECRET}` — **no** public user-facing purge.  
5. Docs: this runbook + `docs/auth-api.md` cron row + `docs/identity-bootstrap.md` status-machine update; unit tests green; CI `lint` / `test` / `typecheck` / `build` green.  
6. F1.8 structured logs with purge **counts** only — never PII, tokens, emails, `sub`, or chat text.  
7. **`nomade-prod` / prod Auth untouched.** Secrets stay in Keeper. Envs: local + `nomade-dev` / Preview only.  
8. iOS: **no UI change** (F2.6b already discloses ≤30d). Apple `/auth/revoke` still deferred.

## Approach decisions (Cap proposes → Isaias approve)

### A. Trigger: daily cron + 24h grace

**Pick: Daily Vercel Cron hits a protected Next.js route; purge any `pending_deletion` where `deleted_at <= now() - interval '24 hours'`.**

| Option | Verdict |
|---|---|
| **A. Daily cron; eligible after 24h grace** | **Chosen.** Accidental soft-delete breathing room **without** a cancel API; still well under the F0.2 ≤30d SLA (in practice purge ASAP after grace). |
| **B. Immediate purge on soft-delete request** | Rejected for V1 — couples user request path to Auth admin delete; no breathing room; harder to test. |
| **C. Wait until day 29–30 only** | Rejected — SLA is a ceiling, not a target; longer Class B residual risk. |

SLA promise to users remains **≤ 30 days** (F0.2 / iOS copy). Operationally we purge after **24h**.

Suggested schedule (UTC): once daily, e.g. `0 4 * * *` (04:00 UTC). Exact hour is ops preference; document in `vercel.json`.

### B. Auth admin deleteUser timing

**Pick: service_role + `auth.admin.deleteUser(userId)` AFTER wiping/de-identifying internal rows.**

Order matters:

1. Scrub / close internal Class B (and stub domain wipes).  
2. Then Auth `deleteUser`.  
3. Then mark `deletion_status = 'deleted'` (Cap default: scrub → Auth → mark `deleted`, with Auth-missing treated as success).

Re-SIWA after Auth delete mints a **new** `auth.users.id` (= new `internal.users.id`), satisfying F2.1.

### C. What to wipe vs keep

**Pick: keep `internal.users` row; scrub PII (`email → null`); set `deletion_status = 'deleted'`; leave `deleted_at`; close any leftover identities; delete Auth user.**

| Option | Verdict |
|---|---|
| **A. Keep row + scrub PII + `deleted`** | **Chosen.** Referential honesty for any future FKs; bootstrap/`me` already treat `deleted` as terminal (`ACCOUNT_DELETED`). |
| **B. Hard-DELETE the `internal.users` row** | Rejected for V1 — breaks UUID-as-FK story and complicates idempotent “already purged” checks. |

**Scrub inventory today (expand when tables land):**

| Target | Action |
|---|---|
| `internal.users.email` | `NULL` |
| `internal.users.deletion_status` | `'deleted'` |
| `internal.users.deleted_at` | leave as-is (soft-delete timestamp) |
| `internal.users.updated_at` | `now()` |
| `internal.auth_identities` still open | set `closed_at = now()` |
| `internal.auth_identities` for user | **DELETE all rows for that `user_id`** after close attempt (Class B; safer than leaving `provider_subject`) |
| Journey / chat / billing | Stub wipe functions — no-ops until tables exist (same keys as export envelope) |
| Class E / G | Retain stripped forms per F0.2 when present; today none |

### D. Idempotency

**Pick:**

- `deletion_status = 'deleted'` already → skip (count as `skippedAlreadyDeleted`).  
- Auth user already missing (`deleteUser` 404 / user-not-found) → treat Auth step as **success**, still ensure row is scrubbed + `deleted`.  
- Soft-delete path unchanged (F2.6).  

Cron may re-run safely the same day.

### E. Surface: cron route only (no public purge)

**Pick: `GET|POST /api/cron/purge-accounts` gated by `Authorization: Bearer ${CRON_SECRET}` matching Vercel Cron; no public user-facing purge; no `requireAccess` user Bearer.**

| Option | Verdict |
|---|---|
| **A. Cron route only** | **Chosen.** Matches Vercel Cron `Authorization` header pattern; smallest attack surface. |
| **B. Also `POST /api/internal/account/purge` for manual admin** | Deferred — if needed later, same secret gate; not required to close F2.6p. |

Manual escape hatch for Preview/dev: curl the cron route with `CRON_SECRET` from Keeper (human). Do not invent or paste secrets into git/chat.

### F. Apple revoke + legal hold + env

| Topic | Cap pick |
|---|---|
| Apple `/auth/revoke` | **Still defer** (no Services ID). Auth `deleteUser` + user removing Nomade under Apple ID settings is the V1 path. |
| Legal hold | **No column today → skip tooling**; document “do not purge if future `legal_hold` flag”; optional no-op `isUnderLegalHold(user) → false` helper so Theo can wire a column later without redesign. |
| Env | Local + Preview / `nomade-dev` only. **`nomade-prod` forbidden.** |
| Observability | F1.8 structured logs: `purged`, `skippedAlreadyDeleted`, `skippedLegalHold`, `authAlreadyGone`, `failed` counts + `requestId`. Never PII. |
| iOS | No UI change. |

## Status machine update

```text
active
  └─ POST /api/account/delete (confirm) ──► pending_deletion  (F2.6: set deleted_at; close auth_identities)
        └─ cron purge (deleted_at <= now()-24h) ──► deleted
              (F2.6p: scrub Class B PII; wipe domain stubs; Auth admin deleteUser;
               keep users row; deletion_status=deleted; leave deleted_at;
               retain stripped Class E/G when present per F0.2)
```

- **No cancel / restore** (F2.6 locked). 24h grace is operational only.  
- While `pending_deletion`: bootstrap/`me` → `ACCOUNT_PENDING_DELETION`; export still allowed (F2.6).  
- After purge `deleted`: bootstrap/`me`/export/delete → `ACCOUNT_DELETED`.  
- Re-signup after Auth delete → **new** UUID + fresh bootstrap.

## Implementation sketch (Theo)

### 1. Code layout (suggested)

| Path | Purpose |
|---|---|

| Docs | This runbook; `docs/auth-api.md` row; `docs/identity-bootstrap.md` machine update |

Reuse: `createServiceClient`, `jsonError` / `ERROR_CODES`, `getRequestId`, `log`. **Do not** use `requireAccess` on the cron route (no user Bearer).

### 2. Eligibility (locked default)

```sql
-- conceptual; implement via PostgREST / service client
select id, deleted_at
from internal.users
where deletion_status = 'pending_deletion'
  and deleted_at is not null
  and deleted_at <= (now() - interval '24 hours');
```

Batch size Cap proposes: process up to **N = 50** users per cron invocation (loop with counts); leftover wait for next daily run (still ≪ 30d). Open decision if Isaias wants a different N.

### 3. Per-user purge steps (Theo)

1. Optional `isUnderLegalHold(userId)` — today always `false`; if true → skip + count `skippedLegalHold`.  
2. Scrub: `UPDATE internal.users SET email = null, updated_at = now() WHERE id = $userId AND deletion_status = 'pending_deletion'`.  
3. Close any still-open identities; then `DELETE FROM internal.auth_identities WHERE user_id = $userId`.  
4. Call stub wipers: `wipeJourney(userId)`, `wipeChat(userId)`, `wipeBilling(userId)` — no-ops returning `{ wiped: 0 }`.  
5. `await service.auth.admin.deleteUser(userId)` — if error indicates user already absent → continue as success (`authAlreadyGone`).  
6. `UPDATE internal.users SET deletion_status = 'deleted', updated_at = now() WHERE id = $userId` (leave `deleted_at`).  
7. Log per-user allow with `userId` + outcome code only — **no email / sub**.

Do **not** call Apple revoke. Do **not** touch other users. Do **not** run against `nomade-prod`.

### 4. Cron auth gate

```text
Authorization: Bearer <CRON_SECRET>
```

- Missing/wrong → `401 UNAUTHENTICATED` (F1.8).  
- Compare with constant-time equality against env secret (no logging of the header value).  
- Vercel Cron sends this header when `CRON_SECRET` is configured on the project (Preview / later Production — Production still human-gated and out of F2.6p apply scope).

### 5. `vercel.json` sketch (no secrets)

```json
{
  "crons": [
    {
      "path": "/api/cron/purge-accounts",
      "schedule": "0 4 * * *"
    }
  ]
}
```

Hobby plan limits apply (daily cron OK). Document in `docs/vercel-preview.md` that Preview may not fire production-like crons the same way — local/manual curl with secret remains the smoke path.

## Risks / watchouts

| Risk | Mitigation |
|---|---|
| Soft delete without purge leaves same Auth UUID on re-login | This task **must** call `deleteUser`; bootstrap already blocks pending/deleted |
| Cron secret leak | Keeper only; never commit; 401 on mismatch; do not log Authorization |
| Accidental prod Auth delete | Env matrix + Cap review; Preview/`nomade-dev` only; refuse prod service role in this task |
| Partial failure (scrubbed but Auth still exists) | Mark failed; retry next cron; prefer Auth-missing success after scrub+mark deleted; alert on `failed > 0` |
| Scrubbed but status still pending | Always set `deleted` after successful Auth (or Auth-missing); tests cover ordering |
| Unique index on identities vs nulling `provider_subject` | Prefer **DELETE** identity rows for the user during purge |
| Vercel Hobby cron quirks on Preview | Document manual curl smoke; do not block merge solely on Preview cron delivery |
| Scope creep into Apple revoke / cancel API / audit table | Cap rejects unless Isaias expands Open decisions |
| Logging PII during purge | Counts + `userId` + outcome codes only; rely on F1.8 denylist |
