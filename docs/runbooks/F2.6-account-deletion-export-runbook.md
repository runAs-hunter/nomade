# F2.6 — Account export + deletion (soft delete; purge later)

**Product:** Nomade  
**Repo:** `runAs-hunter/nomade` (Next.js App Router + Supabase Auth); thin iOS Settings path later (`runAs-hunter/nomade-ios`)  
**Mode:** Dedicated (`D`) for Theo PR after Isaias approves this runbook; Cap reviews PR; Isaias merge gate  
**Date:** 2026-09-29  
**Depends on:** F0.2 Class B/C/D/E/G retention; F2.1 §8–§10 account lifecycle + error codes (PR #12); F2.3 `internal.users` / `auth_identities` + bootstrap (PR #14); F2.5 `requireAccess` + `GET /api/account/me` (`deletionStatus`)  
**Related:** Apple App Store Review Guideline **5.1.1(v)** (in-app account deletion); F2.2 SIWA (native, no Services ID / `.p8` yet); F2.9 rate limits; F3.1 billing retention; F4 journey wipe when tables exist

---

## Goal

Ship **server-side** account export + idempotent soft-deletion that satisfies F2.1 / F0.2 and unblocks Apple’s in-app deletion requirement — without a hard purge job, without touching prod, and without inventing a second auth stack.

**Complete when:**

1. `POST /api/account/export` — Bearer via `requireAccess`; returns a **user-scoped** JSON export of data Nomade currently stores for that `userId` (no other users; no secrets).  
2. `POST /api/account/delete` — Bearer via `requireAccess` + explicit confirm; **idempotent soft delete**: `internal.users.deletion_status → pending_deletion`, set `deleted_at`, close active `auth_identities` (`closed_at`); F1.8 errors.  
3. `GET /api/account/me` continues to surface `deletionStatus` (already F2.5). Bootstrap already rejects `pending_deletion` / `deleted` (F2.3).  
4. Docs: this runbook + short `docs/auth-api.md` route rows; unit tests green; CI `lint` / `test` / `typecheck` / `build` green.  
5. **Optional purge job deferred** (see Approach C) — columns + status machine ready; no cron required to close F2.6.  
6. **`nomade-prod` / prod Auth untouched.** Secrets stay in Keeper.

Thin iOS “Settings → Delete account / Export data” that calls these APIs is **out of the backend PR** unless Cap explicitly expands scope; Apple 5.1.1(v) needs the in-app path before App Review — track as F2.6b / F2.4 follow-up.

## Approach decisions (Cap proposes → Isaias approve)

### A. Soft delete now; hard purge later

**Pick: F2.6 implements soft delete + export only. Optional purge job is a documented follow-up (F2.6p / same epic), not a blocker.**

| Option | Verdict |
|---|---|
| **A. Soft-only in F2.6** (`pending_deletion` + close identities; purge ≤30d later) | **Chosen.** Matches F2.3 column comments; Apple allows delayed completion if timeline is disclosed; keeps PR small and testable without cron infra. |
| **B. Soft + synchronous hard wipe in the same request** | Rejected for V1. Hard wipe must touch Auth admin delete, future Class C/D/E tables, and backup/hold rules — higher blast radius; harder to test. |
| **C. Soft + scheduled purge job in same PR** | Deferred. Add when we have journey/chat rows worth wiping or when privacy policy calendar is frozen. Schema already supports `deleted`. |

**Status machine (locked):**

```text
active
  └─ POST /delete (confirm) ──► pending_deletion  (set deleted_at; close auth_identities)
        └─ (later purge job) ──► deleted          (wipe/de-identify Class B/C/D; Auth admin deleteUser;
                                                   retain labelled Class E/G per F0.2)
```

- **No cancel / restore in V1** (simpler; accidental delete → re-signup = new UUID after purge closes Auth user). Open decision if Isaias wants a grace cancel window — see Open decisions.  
- Idempotent: second `POST /delete` while already `pending_deletion` → **200** with same shape (not an error).  
- `deleted` → `POST /delete` / export → `ACCOUNT_DELETED` (401/410).  
- While `pending_deletion`: bootstrap / most account ops → `ACCOUNT_PENDING_DELETION` (403); **export still allowed** so the user can retrieve a final copy.

### B. What “export” returns (data that leaves)

**Pick: synchronous JSON download of user-scoped rows Nomade stores today; expand the inventory as Class C/D/E tables land.**

F0.2 “user export then delete with account” (Class C) + F2.1 §8 Export. No other user’s data. Never include:

- Access / refresh tokens, Apple identity tokens, authorization codes  
- Service-role keys or any Class H secrets  
- Full raw Apple `sub` in logs (prefix only if needed); export **may** include `provider_subject` inside the user’s own bundle (it is their identity binding) — do **not** log it  
- Other users’ rows; Class A knowledge corpus; Class G raw audit dumps beyond the user’s own consent/account events if any exist

**V1 export envelope (Cap proposes):**

```json
{
  "exportedAt": "<iso8601>",
  "userId": "<uuid>",
  "deletionStatus": "active",
  "account": {
    "createdAt": "<iso8601>",
    "updatedAt": "<iso8601>",
    "emailPresent": true,
    "email": null
  },
  "identities": [
    {
      "provider": "apple",
      "providerSubject": "<sub>",
      "createdAt": "<iso8601>",
      "closedAt": null
    }
  ],
  "journey": [],
  "chat": [],
  "billing": [],
  "notes": [
    "journey/chat/billing arrays empty until those domains ship; format stable for clients"
  ]
}
```

| Field | Rule |
|---|---|
| `account.email` | Include **only if** present on `internal.users` (user’s own Class B). Prefer omitting when null. Never invent. |
| `identities[].providerSubject` | Include in export file (user-owned). Never put in application logs. |
| `journey` / `chat` / `billing` | Empty arrays until F4 / chat-binding / F3 — keeps client schema stable. |
| Delivery | **200** `application/json` body (sync). No object-storage signed URL in F2.6 (data volume is tiny). Revisit if vault (Class F) appears. |

### C. Auth + “reauth” before delete

**Pick: `requireAccess` + explicit JSON confirm string. Fresh Sign in with Apple re-prompt is an iOS UX requirement (AC-01), not a second server secret.**

| Option | Verdict |
|---|---|
| **A. Bearer + `{ "confirm": "DELETE" }`** | **Chosen for API.** Wrong/missing confirm → `400 BAD_REQUEST`. Matches “explicit user intent” without new crypto. |
| **B. Server checks token `iat` within N minutes** | Optional hardening later; skip in F2.6 unless cheap. |
| **C. Separate reauth nonce / step-up token** | Out of V1 — invents protocol surface. |

iOS (follow-up): before calling delete, re-run SIWA (or equivalent step-up) so a stolen unlocked phone cannot one-tap wipe (F2.1 AC-01). Backend still requires a valid Bearer for the env.

Export: Bearer only (no confirm string). Rate-limit later (F2.9).

### D. Supabase Auth user + Apple revoke

**Pick for soft delete:** close `auth_identities` + set `pending_deletion` only. **Do not** call `auth.admin.deleteUser` in the soft-delete request.

**Pick for later purge:** `auth.admin.deleteUser(userId)` so the next Apple sign-in mints a **new** `auth.users.id` (= new `internal.users.id`), satisfying F2.1 “re-signup = new UUID”. Closing identities alone is not enough if Auth keeps the same `sub` → same Auth UUID.

**Apple `/auth/revoke`:** native F2.2 path has **no** Services ID / `.p8`. Cap proposes: **document as open / follow-up** — either (1) add minimal Services ID + key for revoke-only when approaching App Review, or (2) rely on Auth `deleteUser` + user removing Nomade under Apple ID → Sign in with Apple settings. Do **not** block F2.6 soft-delete on revoke wiring.

### E. Subscriptions notice (product copy)

Apple: deleting the app account does **not** cancel App Store subscriptions. F3 billing may not exist yet; still **lock the API/docs note** and require iOS delete UI (when built) to warn + link to subscription management (`showManageSubscriptions` / App Store subscriptions URL). Backend does not cancel StoreKit products in F2.6.

## API contracts

Both routes: Node runtime, `force-dynamic`, F1.8 errors, `x-request-id`, structured logs with `requestId` + `userId` — **never** Authorization header, tokens, full `sub`, or email values in logs (`emailPresent` boolean OK).

### `POST /api/account/export`

| | |
|---|---|
| **Auth** | `requireAccess` (Bearer, env-scoped) |
| **Body** | Empty / ignored |
| **Success 200** | Export envelope above |
| **No `internal.users` row** | `401 UNAUTHENTICATED` “Bootstrap required” (same as `me`) |
| **`deletion_status = deleted`** | `401` or `410` `ACCOUNT_DELETED` |
| **`pending_deletion`** | **200** — export still allowed |
| **IDOR** | N/A — always scoped to `auth.userId` |

### `POST /api/account/delete`

| | |
|---|---|
| **Auth** | `requireAccess` |
| **Body** | `{ "confirm": "DELETE" }` exactly (case-sensitive) |
| **Success 200** | `{ "userId", "deletionStatus": "pending_deletion", "deletedAt": "<iso8601>" }` |
| **Idempotent replay** | Same 200 if already `pending_deletion` |
| **Already `deleted`** | `ACCOUNT_DELETED` |
| **Missing/wrong confirm** | `400 BAD_REQUEST` |
| **No user row** | `401 UNAUTHENTICATED` “Bootstrap required” |

**Soft-delete server steps (Theo):**

1. `requireAccess` → `userId`.  
2. Validate confirm.  
3. service_role: read `internal.users`; branch on `deletion_status`.  
4. If `active`:  
   - `UPDATE internal.users SET deletion_status = 'pending_deletion', deleted_at = now(), updated_at = now() WHERE id = $userId`.  
   - `UPDATE internal.auth_identities SET closed_at = now() WHERE user_id = $userId AND closed_at IS NULL`.  
5. Log allow with `userId` + status transition — no PII payloads.  
6. Return success body.

Do **not** delete `auth.users` here (purge later). Do **not** require journey/chat tables to exist.

|---|---|---|
| `POST /api/account/export` | Protected (new) | Bearer via `requireAccess` |
| `POST /api/account/delete` | Protected (new) | Bearer via `requireAccess` + confirm |

## Risks / watchouts

| Risk | Mitigation |
|---|---|
| Soft delete without Auth `deleteUser` leaves same Auth UUID on re-login | Bootstrap already returns `ACCOUNT_PENDING_DELETION` / `ACCOUNT_DELETED`; purge **must** `deleteUser` before promising clean re-signup — call out in F2.6p |
| Apple Review rejects missing in-app UI | Backend alone ≠ 5.1.1(v); schedule F2.6b iOS Settings path before submission |
| Apple revoke skipped | Document; add Services ID revoke before Review if required |
| Export leaks PII into logs | Log counts/status only; never dump export body |
| Accidental wipe of wrong user | service_role updates always `.eq("id", auth.userId)`; tests for IDOR |
| Scope creep into purge/cron | Cap rejects PR that adds schedulers unless Isaias expands |
| Subscription confusion | iOS copy must warn; backend docs note only |
